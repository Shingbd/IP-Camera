# 智能安防哨兵监控系统——课程设计报告

## 摘要

本课程设计实现了一个基于 Rockchip RK3566 嵌入式平台的智能安防哨兵监控系统。系统利用 GStreamer 多媒体框架实现视频采集、显示与 RTSP 推流，集成 RKNN NPU 加速的 YOLOv8-pose 人体关键点检测模型，实现实时人体姿态估计与行为分析（蹲伏检测、暴力行为检测、人群聚集检测）。系统具备异常事件自动录制功能，采用三段式状态机控制录制启停，并支持通过 RTSP 协议在局域网内实时查看监控画面。整体系统以 C++17 编写，基于 CMake 构建，部署于 ARM Linux 环境。

**关键词**：RK3566；GStreamer；RKNN；YOLOv8-pose；行为分析；RTSP

## 1. 绪论

### 1.1 项目背景

随着人工智能和边缘计算技术的快速发展，智能视频监控系统在安防领域的应用日益广泛。传统监控系统仅提供视频录制与回放功能，缺乏实时智能分析能力。将深度学习模型部署到边缘计算设备上，可以在本地完成实时视频分析，降低对云端算力的依赖，减少带宽消耗，同时保障数据隐私。

Rockchip RK3566 是一款集成 NPU（神经网络处理单元）的 ARM 处理器，提供约 1 TOPS 的算力，适合运行轻量级深度学习模型。GStreamer 是一个成熟的多媒体框架，可灵活构建视频处理流水线。

### 1.2 项目目标

本课程设计旨在实现一个完整的嵌入式智能安防监控系统，具体目标如下：

- 实现摄像头视频实时采集与本地 HDMI 显示
- 集成 YOLOv8-pose 模型，利用 NPU 加速人体关键点检测
- 基于人体关键点实现蹲伏、暴力、聚集三种行为分析
- 实现异常事件自动录制功能
- 支持 RTSP 协议进行网络推流

### 1.3 开发环境

| 项目 | 内容 |
|------|------|
| 硬件平台 | RK3566 SoC（4×Cortex-A55 + 1×NPU） |
| 摄像头 | OV5695（2592×1944，通过 V4L2 接入） |
| 操作系统 | ARM Linux |
| 编程语言 | C++17 / C |
| 构建工具 | CMake ≥ 3.16 |
| 多媒体框架 | GStreamer ≥ 1.16（gstreamer-1.0, gstreamer-app-1.0, gstreamer-rtsp-server-1.0） |
| AI 框架 | RKNN Toolkit（librknnrt.so） |
| 检测模型 | YOLOv8-pose（INT8 量化，.rknn 格式） |

## 2. 系统总体设计

### 2.1 系统架构

系统采用双管道 GStreamer 架构，将摄像头采集管道与本地显示管道分离，解决 autovideosink 与 appsink 在同一管道中可能出现的 preroll 死锁问题。整体架构如下：

```
┌── 摄像头管道 ──────────────────────────────────────────┐
│ v4l2src → videoconvert → videoscale → NV12(640×480)    │
│     → tee                                               │
│         ├─ appsink_ai   (AI 推理 + 绘制线程)             │
│         └─ appsink_rtsp (RTSP 推流线程)                   │
└─────────────────────────────────────────────────────────┘

┌── 显示管道 ────────────────────────────┐
│ appsrc → videoconvert → autovideosink   │
└─────────────────────────────────────────┘

┌── RTSP 管道（每客户端动态创建） ───────────────────────┐
│ appsrc → videoconvert(I420) → mpph264enc → rtph264pay   │
└─────────────────────────────────────────────────────────┘
```

### 2.2 系统功能模块

系统划分为以下功能模块：

1. **视频采集模块**：通过 V4L2 读取 OV5695 摄像头数据，缩放至 640×480 NV12 格式
2. **AI 推理模块**：调用 RKNN API 加载 YOLOv8-pose 模型，对每帧进行 NPU 加速推理
3. **行为分析模块**：基于人体关键点检测结果，分析蹲伏、暴力、聚集行为
4. **画面叠加模块**：在视频帧上绘制检测框、骨架连线、行为标签和录制指示
5. **本地显示模块**：将叠加后的画面通过 HDMI 输出到显示器
6. **RTSP 推流模块**：启动 RTSP 服务器，支持多客户端同时拉流
7. **异常录制模块**：检测到异常行为时自动启动录制，生成 H.264 MP4 文件

### 2.3 系统工作流程

系统启动后的完整工作流程如下：

1. 初始化 RKNN 模型，加载 YOLOv8-pose 的 .rknn 文件
2. 创建 GStreamer 摄像头采集管道和本地显示管道
3. 启动 RTSP 服务器，监听指定端口（默认 7551）
4. 创建 AI 推理线程和 RTSP 推流线程
5. AI 线程循环从 appsink 拉取视频帧，执行 NPU 推理→后处理→行为分析→绘制→推送显示
6. RTSP 线程循环从 appsink 拉取视频帧，通过零拷贝方式推送给所有连接客户端
7. 检测到异常行为时，进入录制状态机，自动记录异常片段

## 3. 系统详细设计

### 3.1 视频采集与管道设计

摄像头管道使用 `v4l2src` 读取 `/dev/video` 设备，通过 `videoconvert` 和 `videoscale` 将 OV5695 原始 2592×1944 分辨率缩放至 640×480，输出 NV12 格式。使用 `tee` 元素将数据流分发给两个 appsink，实现 AI 处理和 RTSP 推流的并行执行。

关键技术要点：

- **零拷贝 RTSP**：tee 直接共享 `GstBuffer`，RTSP 线程仅做 `gst_buffer_ref` 引用计数增加，不进行数据拷贝
- **深拷贝 AI**：tee 共享的内存不可写，AI 线程必须通过 `gst_buffer_copy` 创建副本才能进行绘制

### 3.2 YOLOv8-pose 模型推理

模型推理基于 RKNN Model Zoo 提供的 SDK，在 RK3566 NPU 上运行 YOLOv8-pose 模型。推理流程如下：

```
输入帧 (NV12 640×480)
    ↓
convert_image_with_letterbox() — 缩放到 640×640 RGB888（补黑边）
    ↓
rknn_inputs_set() — 设置输入 tensor
    ↓
rknn_run() — NPU 推理 (~62ms)
    ↓
rknn_outputs_get() — 获取 4 个输出 tensor
    ↓
post_process() — DFL 解码 + NMS + 关键点提取 + 坐标映射
    ↓
绘制检测框、骨架连线、关键点
    ↓
rknn_outputs_release() — 释放输出缓冲区
```

模型输出包括 4 个 tensor：

| 索引 | 形状 | 内容 |
|------|------|------|
| 0 | [1, 65, 80, 80] INT8 | 小尺度检测头 |
| 1 | [1, 65, 40, 40] INT8 | 中尺度检测头 |
| 2 | [1, 65, 20, 20] INT8 | 大尺度检测头 |
| 3 | [1, 17, 3, 8400] FP16 | 关键点输出（17 个关键点 × 3 值 × 8400 候选） |

每个检测头的前 64 维是 DFL（Distribution Focal Loss）box 参数，第 65 维是人脸置信度。模型输出的关键点包含 17 个人体关键点（鼻、眼、耳、肩、肘、腕、髋、膝、踝），每个关键点输出 (x, y, confidence) 三元组。

### 3.3 行为分析算法

行为分析模块基于人体 17 个关键点坐标和检测框信息，实现三种异常行为检测。

#### 3.3.1 蹲伏检测

利用人体关键点的几何比例关系判断蹲伏姿态：

```
r1 = (髋到踝距离) / (总身高)
r2 = (膝到踝距离) / (髋到踝距离)

if r1 < 0.45: score += 0.6
if r2 < 0.40: score += 0.4
```

站立姿态下 r1 ≈ 0.5~0.6，r2 ≈ 0.5~0.6；蹲伏姿态下两个比值均显著减小。综合得分 > 0.5 判定为蹲伏。

#### 3.3.2 暴力行为检测

采用两种启发式规则：

1. **框重叠检测**：两个人检测框的 IOU > 0.3，表示身体高度重叠，有冲突嫌疑
2. **异常姿态检测**：手腕高于肩膀（举手）或手腕横向距离超过框宽 1.2 倍（手臂张开），表示异常姿势

综合得分 > 0.4 判定为暴力行为。

#### 3.3.3 人群聚集检测

检测画面中人数是否达到设定的聚集阈值（默认 ≥ 4 人），超过阈值触发聚集警报。

### 3.4 异常录制状态机

录制系统采用三段式状态机设计，避免瞬时误报导致的无效录制：

```
IDLE ──(检测到异常)──→ WARMING
WARMING ──(持续异常 ≥3s)──→ ACTIVE（开始录制）
WARMING ──(连续正常 ~1s)──→ IDLE（取消预录）
ACTIVE ──(连续正常 ~2s + 已录 ≥5s)──→ IDLE（停止录制）
ACTIVE ──(未达 5s)──→ 安全保持，不停止
```

录制文件格式为 `record_YYYYMMDD_HHMMSS.mp4`，采用 `mpph264enc` 硬件编码器 + `mp4mux` 封装，录制内容包含 AI 叠加画面。

### 3.5 RTSP 推流设计

系统内置 GStreamer RTSP 服务器，支持多客户端并发拉流：

- **端口**：默认 7551（可通过 `-p` 参数配置）
- **挂载点**：`/test`
- **编码格式**：NV12 → I420 → mpph264enc（硬件编码）→ rtph264pay
- **客户端管理**：通过 `media_configure_cb` 和 `media_finished_cb` 回调动态管理客户端连接
- **推流方式**：RTSP 线程从 appsink 获取帧后，通过 `gst_buffer_ref` 零拷贝方式推送给所有客户端

### 3.6 画面叠加信息

每帧画面实时叠加以下信息（从左上角开始排列）：

| 内容 | 颜色 | 说明 |
|------|------|------|
| `people=N` | 绿色 | 当前检测人数 |
| `CROWD ALERT` | 红色 | 人群聚集告警 |
| `CROUCH` | 黄色 | 蹲伏行为告警 |
| `VIOLENCE` | 红色 | 暴力行为告警 |
| `REC` | 红色（右上角） | 录制中指示 |

此外，每个人体目标绘制蓝色检测框、黄色关键点和橙色骨架连线，并显示置信度百分比。

## 4. 系统实现与测试

### 4.1 项目文件结构

```
Main_project/
├── cam.cpp                 # 主程序（管道创建/AI推理/录制/RTSP）
├── behavior_detection.h    # 行为分析接口（BehaviorReport结构体）

├── CMakeLists.txt          # CMake构建配置（C++17, GStreamer, RKNN）
├── 3rdpart/
│   └── rknn_model_zoo/     # RKNN模型库（postprocess/image_utils/image_drawing）
├── docs/
│   ├── DEBUG_SUMMARY.md    # 调试日志
│   └── RKNN_FLOW.md        # RKNN推理流程文档
└── README.md               # 项目说明文档
```

### 4.2 构建与运行

#### 构建步骤

```bash
mkdir build && cd build
cmake ..
make -j4
```

CMake 构建系统自动查找 GStreamer、RKNN 工具链和 Threads 库依赖，编译生成 `cam` 可执行文件。

#### 运行方式

```bash
./cam                          # 默认 /dev/video10, model/yolov8_pose.rknn
./cam -d 0                     # 使用 /dev/video0
./cam -d 0 model/custom.rknn   # 指定设备和模型
./cam -p 8554                  # 指定RTSP端口
```

#### 查看 RTSP 流

```bash
ffplay rtsp://192.168.x.x:7551/test
```

### 4.3 命令行参数

| 参数 | 简写 | 默认值 | 说明 |
|------|------|--------|------|
| `--port` | `-p` | `7551` | RTSP 监听端口 |
| `--device` | `-d` | `10` | 摄像头设备号（`/dev/videoNUM`） |
| `(位置参数)` | | `model/yolov8_pose.rknn` | RKNN 模型路径 |

## 5. 总结与展望

### 5.1 工作总结

本课程设计成功实现了一个基于 RK3566 的智能安防哨兵监控系统，主要完成以下工作：

1. 基于 GStreamer 构建了双管道视频处理架构，实现摄像头采集、AI 处理、本地显示、RTSP 推流的并发运行
2. 集成 RKNN Model Zoo SDK，在 NPU 上高效运行 YOLOv8-pose 人体关键点检测模型
3. 设计了基于关键点几何比例的行为分析算法，实现蹲伏、暴力、聚集三种异常行为检测
4. 实现了三段式状态机控制的异常自动录制功能，有效减少误报录制
5. 搭建了 RTSP 流媒体服务器，支持局域网多客户端实时查看

通过学习本课程设计，加深了对嵌入式 Linux 多媒体编程、边缘 AI 推理部署、计算机视觉算法等知识的理解，积累了 C++ 多线程编程与 GStreamer 框架的实践经验。

### 5.2 存在的不足与改进方向

- **帧率优化**：当前约 15 FPS，可通过模型量化、NPU 多核并行等方式提升
- **行为算法改进**：当前基于启发式规则的检测方法存在一定误报率，可考虑引入时序模型（如 LSTM）提升准确性
- **前端界面**：当前系统无 Web 管理界面，可增加 Web 端实时预览与告警管理功能
- **多路摄像头**：当前仅支持单路摄像头，后续可扩展支持多路同时监控
